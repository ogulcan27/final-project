## User Story

**As a** beginner, **I want to** open FinAlly and watch real or simulated prices stream into my watchlist, **so that** I can see the market moving and know whether the data is real.

This plan delivers the "know whether the data is real" part on screen: a source badge with its reason, a STALE warning, an honest Day % label, and a connection dot that recovers on its own.

<objective>
This plan builds the header for the backend status contract from plan 01-02:
- The LIVE / SIMULATED badge with the reason as a hover tooltip (DATA-03, D-14).
- The amber STALE state, with dimmed prices (DATA-04, D-15, D-16).
- The Day % label that says when it is a session measure (DATA-05, D-06).
- The green / yellow / red connection dot that recovers after a server restart (UI-03, D-17), using the timer and CLOSED handling from research Pattern 8.

Purpose: success criteria 3 and 4 say "header badge shows LIVE or SIMULATED with the reason on hover", "STALE when prices stop arriving", and "connection dot ... turns red when the server is down and green again when it comes back".
Output: the tested pure helpers `hooks/connection.ts` and `shared/status.ts`, the `Header`, `Badge` and `ConnectionDot` components, the upgraded `usePriceStream`, and Watchlist header and dimming.
</objective>

   - DISCONNECTED_AFTER_MS = 5000.

   - READY_CONNECTING = 0 and READY_CLOSED = 2, matching the EventSource readyState values.
   - type ConnectionEvent: {type: "open"}, {type: "error"; readyState: number}, or {type: "timeout"}.
   - nextConnection(current: ConnectionState, event: ConnectionEvent): ConnectionState. Rules:
     - open gives "connected".
     - error with READY_CLOSED gives "disconnected".
     - error with any other readyState gives "reconnecting", except that "disconnected" stays "disconnected".
     - timeout turns "reconnecting" into "disconnected" and leaves any other state unchanged.

The browser does not retry a closed stream (Pitfall 6), and only one EventSource exists at a time.

## Flagged Assumptions (edge probe, unclassified, unresolved)

- **A-07-1 (DATA-03):** The "hover tooltip" is the native `title` attribute. It appears on mouse hover and is read by screen readers, but it does not appear on touch screens. Desktop is the primary target (PLAN.md section 2). A custom tooltip component is not built.

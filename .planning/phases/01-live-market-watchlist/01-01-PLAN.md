## User Story

**As a** beginner, **I want to** open FinAlly and watch real or simulated prices stream into my watchlist, **so that** I can see the market moving and know whether the data is real.

This plan is the Walking Skeleton tracer (see `01-SKELETON.md`): the thinnest real path through every layer the phase touches. Later plans in this phase expand it without changing its architecture.

<objective>
Prove the whole stack end to end. SQLite is created and seeded on first start (D-01, D-02, D-07). The lifespan starts the market source with the stored watchlist. The SSE route pushes one batched envelope per cache change (D-03, the `prices` half; plan 01-02 adds `status`). FastAPI serves the Next.js static export at `/` from the same origin, and the page renders the streaming tickers.

Purpose: catch an architectural dead end after one commit, not after ten.
Output: the frontend scaffold with one live page, `backend/app/db/` with schema, seed and watchlist read, the version-gated stream, a DB-backed lifespan with a static mount, and green tests including a real-HTTP end-to-end test.

   backend/app/db/connection.py contains:
   - Constants SCHEMA_VERSION = 1, DEFAULT_USER = "default" and STARTING_CASH = 10000.0.
   - SCHEMA: one SQL string of CREATE TABLE IF NOT EXISTS statements. Every id column is TEXT PRIMARY KEY, and every user_id column is TEXT NOT NULL DEFAULT 'default'. The tables are:
     - users_profile: id TEXT PRIMARY KEY DEFAULT 'default', cash_balance REAL NOT NULL DEFAULT 10000.0, created_at TEXT NOT NULL.
     - watchlist: id, user_id, ticker TEXT NOT NULL, added_at TEXT NOT NULL, UNIQUE(user_id, ticker).
     - positions: id, user_id, ticker TEXT NOT NULL, quantity REAL NOT NULL, avg_cost REAL NOT NULL, updated_at TEXT NOT NULL, UNIQUE(user_id, ticker).

   - connect(path: Path) -> sqlite3.Connection: sqlite3.connect(path, isolation_level=None), then PRAGMA foreign_keys = ON and PRAGMA busy_timeout = 5000. Keep the default journal mode (not WAL).
   - transaction(path: Path): a contextlib.contextmanager that connects and executes BEGIN IMMEDIATE, then yields the connection. It COMMITs on success, ROLLBACKs and re-raises on an exception, and always closes.
   - init_db(path: Path) -> None:
     - Create path.parent with parents=True and exist_ok=True.
     - On a plain connection, run executescript(SCHEMA) before any BEGIN (executescript commits implicitly), then set PRAGMA user_version to SCHEMA_VERSION.
     - In one transaction, run INSERT OR IGNORE INTO users_profile (id, cash_balance, created_at) with DEFAULT_USER, STARTING_CASH and now.
